claude-view

A desktop app that opens a dedicated window for each Claude Code CLI session, mirrors its terminal character-by-character, and keeps a readable, costed record of everything the session did.

High-level design

System architecture One process: the registry, the loopback server, every PTY and every webview — and what sits outside it.
How a session becomes each view Produce → capture → read → derive → present, and why it takes three paths rather than one.

Low-level design

The read path Nine modules over one set of files, one attribution decision, and the two leaves.
The frontend One bundle, four roots chosen by query string, three strictly divided transports.
Session state Two signals merged, never mixed — and what is allowed to claim a session ended.

Written

Architecture: HLD & LLD → All 14 Rust modules and 25 TypeScript files, 24 IPC commands, 8 HTTP routes, the WebSocket protocol, every on-disk format, eight runtime flows, the measurements behind each constant, and an honest list of what an audit found. Domain glossary → Run vs type, turn, replay, baseline, hosted vs watched, and what “live” is allowed to mean.
Every diagram is interactive — pan, zoom, search, guided views, PNG/SVG export. Each ships with the .spec.json it was generated from.
